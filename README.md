# Ритм — голосовой ассистент задач и встреч

Локальный органайзер с FastAPI, SQLite, минимальным веб-интерфейсом и двумя режимами диалога: **DeepSeek tool calling** при наличии ключа и детерминированный `RuleDialogue` как рабочий fallback. Бизнес-логика не зависит от модели: LLM только выбирает инструмент и передаёт JSON-аргументы, а SQL выполняет проверенный серверный код.

> **Честный статус:** CRUD, локальное хранение, импорт 1000 событий, поиск, браузерный голосовой ввод, шесть инструментов, `ChatRouter`, DeepSeek-адаптер и fallback покрыты автоматическими тестами. Реальный smoke-test через LiteRouter и `POST /api/chat` успешно выполнен: модель выбрала `create_event`, запись создана во временной БД, `llm_connected=true`. Семантический поиск на embeddings и автоматическая compaction не реализованы.

## Запуск на Windows 10/11

1. Установите [Python 3.11+](https://www.python.org/downloads/windows/) с опцией **Add Python to PATH**. Интернет нужен для установки Python-зависимостей и работы DeepSeek.
2. Распакуйте ZIP в папку без ограничений на запись, например `C:\Projects\ritm`.
3. Дважды нажмите **`start_windows.bat`**. Он создаст `.venv`, установит зависимости и запустит сервер.
4. Откройте **http://127.0.0.1:8000**. Документация REST API: **http://127.0.0.1:8000/docs**.
5. Для остановки нажмите `Ctrl+C` в окне сервера.

Альтернативно в PowerShell:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python run.py
```

Если PowerShell блокирует `Activate.ps1`, используйте `\.venv\Scripts\python.exe -m pip install -r requirements.txt`, затем `\.venv\Scripts\python.exe run.py`. Не требуется менять системную политику PowerShell.

При первом запуске автоматически импортируются записи из `data/events.csv` в `assistant.db`. Повторный запуск **не создаёт дубликаты**. Созданные и изменённые записи не теряются при перезапуске. Для чистого старта удалите файл `assistant.db` **при выключенном приложении** (потеряются все изменения) или укажите новый путь `ASSISTANT_DB`.

### Настройки

По умолчанию используется часовой пояс `Europe/Moscow`. Чтобы переключиться на ваш, перед запуском в PowerShell:

```powershell
$env:ASSISTANT_TIMEZONE="Europe/London"
$env:ASSISTANT_DB="C:\Projects\ritm\assistant.db"
python run.py
```

Или измените `start_windows.bat`, добавив `set "ASSISTANT_TIMEZONE=Europe/London"` после `cd`. **Часовой пояс нужно выбрать ДО первого импорта**: он сохраняется у каждой записи. На Windows для баз IANA поставляется зависимость `tzdata`.

Другие настройки: `ASSISTANT_IMPORT_SEED=0` — отключить загрузку CSV, `ASSISTANT_SEED_CSV` — задать другой исходный CSV. `data/events.csv` намеренно включён в архив.

### DeepSeek (опционально)

Без ключа приложение полностью запускается и использует локальные правила. Для свободных естественноязычных запросов задайте ключ **в окружении, не в исходниках** перед запуском:

```powershell
$env:DEEPSEEK_API_KEY="ваш_ключ"
python run.py
```

По умолчанию выбраны LiteRouter `https://api.literouter.com/v1` и free-модель `deepseek-v4.1-flash-1017:free`. Для другого OpenAI-совместимого провайдера доступны `DEEPSEEK_BASE_URL`, `DEEPSEEK_MODEL` и `DEEPSEEK_TIMEOUT_SECONDS=30`. Файл `.env.example` — только справка: переменные нужно экспортировать в окружение, ключ в репозиторий не добавляется.

`ChatRouter` сначала выполняет понятную команду через локальные правила, а незнакомую формулировку отправляет в `DeepSeekProvider`. Модель получает текущие `now`/IANA timezone и JSON Schema шести инструментов, но не получает SQL или доступ к БД. Недостающие поля, выбор среди нескольких записей и подтверждение отмены обрабатывает сервер.

Создание, изменение и отмену подтверждает сервер по фактическому результату БД. Результаты списка/поиска/get модель может кратко описать дополнительным вызовом; при его сбое сохраняется детерминированный ответ с уже полученными данными. При timeout, HTTP 401/429/5xx или malformed JSON выполняется контролируемый fallback без повторения мутации.

`GET /api/health` различает `llm_configured` (провайдер настроен) и `llm_connected` (последний вызов DeepSeek успешен). Сетевой health-check при старте не выполняется.

## Что можно проверить

* Кнопка **Новое событие**: задача без даты или с датой, встреча с обязательными датой/временем, напоминание.
* **Расписание**: фильтр по датам и типам, поиск по названиям, пагинация, отметка выполнения, редактирование и отмена.
* **Диалог**: «Напомни мне завтра в 10 утра позвонить Ивану», «Добавь встречу с командой завтра», затем «в 15:00», «Что у меня сегодня?», «Найди задачу про договор», «Перенеси её на пятницу» после однозначного выбора.
* **Диктовка**: кнопка микрофона при наличии Web Speech API в Chrome/Edge; голос распознаётся браузером и подставляется в поле текста. Есть опциональная озвучка ответа браузером.
* **Инструменты**: `GET /api/tools` возвращает строгие схемы для LLM; публичного endpoint произвольного выполнения инструментов нет.

В резервном режиме набор формулировок намеренно ограничен. Для неподдержанной фразы интерфейс честно сообщает об ограничении локального parser.

## Архитектура

```
Browser (vanilla JS, SpeechRecognition, speechSynthesis)
                |
           REST /api/*
                |
   FastAPI --> ChatRouter --> DeepSeekProvider --> DeepSeek API
                |  |
                |  --> RuleDialogue (локальный fallback)
                |
           ToolRegistry
                |
              Planner
           /    |    \
  validation   search   conflict checks
                |
              SQLite
        events/sessions/messages
```

| Модуль | Ответственность |
| --- | --- |
| `assistant/models.py` | Pydantic-схемы, строгая валидация входных аргументов |
| `assistant/database.py` | SQL-схема, транзакции `BEGIN IMMEDIATE`, индексы, WAL |
| `assistant/service.py` | Бизнес-логика, конфликты встреч, статусы, CSV, хранение диалога |
| `assistant/search.py` | Оффлайн поиск с нормализацией и нечёткими совпадениями (НЕ embeddings) |
| `assistant/dates.py` | Детерминированный разбор типовых русских дат/времени |
| `assistant/dialogue.py` | Ограниченный резервный обработчик типовых команд и уточнений |
| `assistant/routing.py` | Единый маршрут диалога, pending-состояния, выбор записи и гибридные ответы |
| `assistant/deepseek.py` | OpenAI-совместимый HTTP-клиент DeepSeek, timeout и проверка ответа |
| `assistant/deepseek_provider.py` | Перевод DeepSeek tool calls в безопасный `ParsedCommand` |
| `assistant/tools.py` | Шесть инструментов с JSON Schema, изолированная диспетчеризация |
| `assistant/api.py` | HTTP маршруты и перевод доменных ошибок в 404/409/422 |
| `web/*` | Адаптивный UI без сборщика и внешнего JS CDN |
| `tests/*` | Автоматические проверки без сетевых вызовов и реальной LLM |

Подробности: [ARCHITECTURE.md](ARCHITECTURE.md), [LLM_INTEGRATION.md](LLM_INTEGRATION.md), [TECHNICAL_DOCUMENTATION.md](TECHNICAL_DOCUMENTATION.md).

## API в двух примерах

Создать встречу:

```powershell
$body = @{kind="meeting"; title="Планёрка"; scheduled_date="2026-11-05"; scheduled_time="15:00"; duration_minutes=60} | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/api/events -ContentType 'application/json' -Body $body
```

Посмотреть задачи за период:

```powershell
Invoke-RestMethod 'http://127.0.0.1:8000/api/events?from_date=2026-11-02&to_date=2026-11-08&kind=task'
```

Дополнительно: `PATCH /api/events/{id}`, `POST /api/events/{id}/cancel-request`, `GET /api/search?q=договору`, `POST /api/chat`, `GET /api/sessions/{session_id}/history`, `GET /api/tools`.

Отмена двухшаговая: `cancel-request` создаёт pending-подтверждение, затем через `POST /api/chat` отправляется «да» или «нет» с тем же `session_id`. Прямой `DELETE /api/events/{id}` и `PATCH status=cancelled` возвращают 409.

Ответы на ошибки: `404` — запись не найдена, `409` — конфликт встречи, отмена без подтверждения или устаревшая версия, `422` — невалидные аргументы. `expected_version` предотвращает случайную перезапись параллельных изменений.

## Данные и намеренные ограничения

Исходный CSV содержит **ровно `id,date,time,text`**, без поля типа записи. Поэтому все 1000 импортированных элементов сохраняются как `task` с источником `csv` и исходным внешним ID. **Мы не пытаемся угадать по тексту, что запись была встречей или напоминанием**. Импорт атомарен, его можно повторять. Изменение CSV не перезаписывает уже импортированные события.

* Встреча/напоминание требуют даты и времени; у задачи срок необязателен.
* Встречи по умолчанию занимают 60 минут; пересечения запрещаются, включая переход через полночь. Это намеренное продуктовое решение для прототипа.
* Отмена — soft delete (`status=cancelled`). Запись остаётся доступна через `get`, по умолчанию исключается из списков.
* Все датированные операции используют IANA timezone события. Несуществующее локальное время в DST отклоняется; для неоднозначного осеннего часа используется первое вхождение (`fold=0`).
* Поиск поддерживает нормализацию `ё/е`, распространённые окончания и небольшие опечатки; DeepSeek может предложить синонимы после пустого результата. Векторный semantic search не используется.
* Фоновых будильников, push-уведомлений, внешней синхронизации календаря, повторяющихся событий, ролей и нескольких учётных записей **нет**.
* Веб-приложение и API не аутентифицированы: сервер по умолчанию слушает только `127.0.0.1`. **Не публикуйте его в интернет через туннель без аутентификации, ограничения доступа и защиты данных.**
* Web Speech API зависит от браузера и может использовать облачное распознавание. Локальная бизнес-логика не означает офлайн STT. Не храните секретные данные, если используете браузерный голосовой ввод без проверки его политики.
* История диалога сохраняется в SQLite, но в текущий `LLMContext` не передаётся. Автоматическая compaction не реализована.

## Тесты

```powershell
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

Тестируются создание и валидация, транзакции, конфликты и границы времени, DST, статусы, оптимистичные версии, API, tools, русские даты, уточняющий диалог, выбор среди совпадений, хранение и идемпотентный CSV-импорт. DeepSeek проверяется без сети: tool calls, поиск синонимов, гибридные ответы, подтверждение отмены, malformed JSON, HTTP-ошибки и отсутствие повторных мутаций. Тесты изолированы во временных базах. CI описан в `.github/workflows/tests.yml`.

## Сдача тестового

Исходники, README и DeepSeek-адаптер готовы; реальный LiteRouter smoke-test пройден. **Ссылки на GitHub и работающий публичный прототип создаются отдельно.** Перед публичной сдачей остаётся проверить более широкий набор свободных запросов и безопасно развернуть проект.

## Подключение другой LLM

Точка подключения сохранена: `create_app(llm_provider=...)`, интерфейс `assistant/llm_provider.py`, схемы `assistant/contracts.py`. Без явного провайдера и без `DEEPSEEK_API_KEY` используется `NullLLMProvider`. Полный контракт и правила безопасности описаны в [LLM_INTEGRATION.md](LLM_INTEGRATION.md).
