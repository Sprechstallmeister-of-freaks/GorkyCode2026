# Минимальный сценарий демонстрации

1. Запустить `start_windows.bat`. Открыть `http://127.0.0.1:8000`. Проверить `GET /api/health` — количество событий 1000 (если база свежая).
2. В поиске по списку набрать «договору»: найти связанные записи без точного совпадения словоформы.
3. Открыть «Новое событие», создать встречу с датой и временем.
4. Попытаться поставить вторую встречу на пересекающееся время; увидеть ошибку 409.
5. Создать задачу, отметить выполненной, перезапустить сервер, проверить что статус сохранился.
6. В диалоге: «Добавь встречу с дизайнером завтра» → вопрос о времени → «в 15:00» → подтверждение.
7. В диалоге: «Перенеси её на послезавтра» — время остаётся прежним.
8. В диалоге: «Что у меня сегодня?» и «Найди задачу про договор».
9. Без `DEEPSEEK_API_KEY` показать автоматический fallback на нераспознанной фразе. С ключом дополнительно проверить свободную формулировку и подтверждение отмены записи.
10. Открыть `/docs`, показать схемы API и `/api/tools`; в `/api/health` различить `llm_configured` и `llm_connected`.

Реальный LiteRouter smoke-test уже пройден: свободная фраза через `/api/chat` создала запись, `llm_connected=true`. Для повторной демонстрации задайте действующий ключ; без него показывайте рабочий локальный fallback.
